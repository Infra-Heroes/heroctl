# heroctl

The command-line interface for the InfraHeroes platform.

## Usage
Standard build:
```bash
make build
./heroctl --help
```

## Development
Use the `Makefile` for tasks:
- `make build`: Build the binary
- `make test`: Run tests
- `make fmt`: Format code
- `make tidy`: Tidy dependencies

## Personal Access Tokens (PAT)

`heroctl` supports authentication via Personal Access Tokens (PATs). These are permanent tokens generated by `hero-api` that can be scoped.

### 1. Creating a Token
To create a new token, run:
```bash
./heroctl tokens create --name "my-ci-token" --scope deploy
```
* **Scope options:**
  - `deploy`: Restricted to deployment-related actions (fetching projects, registry credentials, listing/submitting deployments, checking status). Other management actions (like creating/deleting projects, managing org members) are blocked.
  - `all`: Full access matching the user's role.

* **IMPORTANT:** The raw token (starting with `hero_pat_`) is printed **only once** upon creation. Make sure to copy it immediately.

### 2. Listing Tokens
To list all active tokens:
```bash
./heroctl tokens list
```
This displays their metadata, scope, creation date, and last used timestamp.

### 3. Revoking/Deleting a Token
To delete/revoke a token, run:
```bash
./heroctl tokens delete <TOKEN_ID>
```

### 4. Using the Token in CI/CD
You can authenticate non-interactively in headless or CI/CD environments (e.g. GitHub Actions, Woodpecker) by passing the token to any `heroctl` command using the global `--token` flag:
```bash
./heroctl deploy --project webpage --token hero_pat_...
```
Alternatively, log in non-interactively on a server to store it in the local config:
```bash
./heroctl login --token hero_pat_...
```
